# LACS — Linux Access Control Setup

Система настройки и управления доступом на Linux-сервере: роли пользователей, временные разрешения на административные действия, ограниченное терминальное окружение и аудит.

LACS предназначен для серверов, где нужно делегировать конкретные операции на ограниченный срок. Доступ определяется ролью, текущей политикой, разрешённой операцией и объектом действия. Основной интерфейс — терминал, включая работу по SSH.

> **Статус:** MVP. Этот README описывает целевое поведение по спецификации версии 1.0. В текущем репозитории исходный код и установщик ещё не опубликованы; наличие описания функции не подтверждает её реализацию или прохождение приёмки.

## Возможности MVP

- Настройка ролей, системных учётных записей и постоянных правил доступа.
- Выдача, просмотр и отзыв временных разрешений — **грантов**.
- Выполнение фиксированных административных операций через привилегированный посредник.
- Управление разрешёнными учётными записями и группами в пределах области LACS.
- Обслуживание разрешённых служб, просмотр журналов и состояния системы.
- Ограниченный терминал для роли с минимальными правами.
- Доступ к общей файловой области согласно роли и файловым разрешениям.
- Аудит выдачи разрешений, исполнения операций, отказов и отзывов.

## Роли и доступ

| Роль | Назначение | Временный доступ |
|---|---|---|
| `root` | Полное управление системой, политиками и LACS | Выдача и отзыв разрешений в пределах административной модели |
| `admin` | Администрирование системы, пользователей и прав через утверждённый механизм повышения привилегий | Одобрение расширения полномочий оператора |
| Оператор | Повседневное обслуживание в рамках постоянных полномочий | Управление разрешёнными пользователями и группами по гранту |
| `ubuntu` | Обычный пользователь без постоянного `sudo` | Утверждённые операции обслуживания по разрешению `root` |
| `user` | Минимальный доступ в ограниченном окружении | В соответствии с назначенной ролью и политикой |

Имя системной учётной записи оператора задаётся при настройке. Числовые UID и GID не фиксируются в модели продукта.

Администратор с возможностью выполнять произвольные действия от `root` входит в доверенную границу системы. LACS не обеспечивает защиту от администратора, способного изменять код, политики и состояние механизма доступа.

## Как работают временные разрешения

1. Издатель выбирает получателя, операции и срок действия.
2. LACS проверяет полномочия издателя, политику получателя и допустимую длительность, затем сохраняет грант и событие аудита.
3. Получатель запрашивает выполнение операции. Выдача гранта сама по себе ничего не запускает.
4. Перед каждым новым запуском исполнитель проверяет личность инициатора, грант, текущую политику, аргументы и объект действия.
5. После отзыва или истечения срока грант больше не допускает новые запуски.

| Получатель | Кто выдаёт | Срок по умолчанию | Максимальный срок |
|---|---|---|---|
| Оператор | `root` или `admin` | 15 минут | 60 минут |
| `ubuntu` | `root` | 30 минут | 120 минут |

Это базовые параметры MVP; значения задаются конфигурацией и проверяются системой. Время хранится в UTC.

Грант содержит уникальный идентификатор, получателя, издателя, явный перечень операций, время создания и окончания, а также отметку отзыва. Выбор «всех разрешённых операций» разворачивается в конкретный список при выдаче: новые операции не добавляются в существующие гранты автоматически.

Временное разрешение не выдаёт неограниченный `sudo`, привилегированную группу или произвольную root-оболочку. Уже начатая операция не прерывается автоматически при отзыве или истечении срока.

## Операции

### Управление учётными записями

Для оператора по временному разрешению предусмотрены:

- создание обычных пользователей в разрешённой области имён;
- удаление управляемых пользователей с сохранением домашнего каталога;
- блокировка и разблокировка пароля;
- смена пароля со скрытым вводом;
- создание и удаление управляемых групп, изменение их состава.

Грант не даёт права изменять посторонние, системные или административные учётные записи. Блокировка пароля не означает отключение входа по SSH-ключу и других способов аутентификации.

### Обслуживание системы

Для роли `ubuntu` по разрешению `root` предусмотрены:

- просмотр состояния, запуск, остановка и перезапуск разрешённых служб;
- перечитывание настроек, включение и отключение автозапуска разрешённых служб;
- ограниченный просмотр журналов служб и ядра;
- просмотр слушающих портов и связанных процессов;
- обновление индекса пакетов;
- перезагрузка и выключение системы.

Службы выбираются из явного разрешённого списка. Обновление индекса пакетов не разрешает установку, удаление или обновление пакетов. Совокупное разрешение для `ubuntu` включает перезагрузку и выключение; интерфейс должен показывать полный состав выдаваемых операций.

### Подключаемые компоненты

Для Nginx спецификация предусматривает проверку конфигурации и её перечитывание после успешной проверки. Подключение операций выполняется отдельно от установки стороннего ПО и подчиняется общим правилам авторизации и аудита.

## Архитектура и стек

Логические компоненты MVP:

| Компонент | Ответственность |
|---|---|
| Клиент | Интерактивные команды и обращения с полностью заданными параметрами |
| Политика доступа | Правила ролей, операций, целей и сроков |
| Хранилище грантов | Сохранение разрешений и состояния отзыва |
| Привилегированные исполнители | Независимая проверка запросов и выполнение фиксированных операций |
| Реестр объектов | Учёт пользователей и групп, управляемых LACS |
| Аудит | Регистрация действий, результатов и отказов без сохранения секретов |

Базовая среда — **Linux**, **systemd**, **OpenSSH**, системные пользователи и группы, файловые разрешения и ACL. Прикладной стек по спецификации:

- **Python 3**, стандартная библиотека;
- **Unix-сокеты** с проверкой личности клиента средствами ОС;
- **JSON** для конфигурации и грантов;
- **SQLite** для реестра управляемых объектов;
- **системный журнал** для аудита.

Клиент не является источником административных полномочий. Исполнители используют фиксированные обработчики и системные утилиты с проверенными аргументами; пользовательский ввод не передаётся системной оболочке как произвольная команда.

**Стек будет меняться в следующих версиях.** Язык, хранилища и организация процессов могут быть заменены с сохранением согласованной модели доступа, контрактов операций и требований к аудиту. Миграции должны учитывать существующие данные и возможность восстановления.

## Ограниченное окружение

Для роли `user` предусмотрен терминал с фиксированным набором действий для навигации и чтения доступных файлов. Проверка путей должна исключать выход за разрешённые области, в том числе через ссылки и подмену пути.

SSH-контекст должен ограничивать запуск удалённых команд, переадресацию, пользовательские стартовые сценарии и файловые подсистемы, позволяющие обойти терминал. Этот механизм контролирует соответствующий SSH-доступ; изоляция остальных сервисов и процессов требует отдельной настройки.

## Установка и запуск

Инструкции установки и запуска будут добавлены вместе с исходным кодом и проверенной процедурой развёртывания. Сейчас репозиторий можно получить командой:

```bash
git clone https://github.com/vtjvlad/lacs-server.git
cd lacs-server
```

Текущий `package.json` содержит метаданные, но не предоставляет рабочих команд установки или запуска LACS. Версия этого файла не обозначает подтверждённый релиз MVP. Конкретные поддерживаемые дистрибутивы Linux и минимальная версия Python пока не зафиксированы в репозитории.

По спецификации установка должна включать проверку среды, сопоставление ролей и учётных записей, настройку допустимых целей и сроков, размещение компонентов, инициализацию состояния и настройку служб. Обновление должно сохранять гранты, реестр, системные идентификаторы и согласованные способы административного входа.

## Проверка MVP

Приёмка опирается на наблюдаемое поведение ОС, ответы LACS и события журнала. Основные сценарии:

- разрешения выдаются только уполномоченным издателем с допустимым составом и сроком;
- выполнение допускается только для разрешённой операции и объекта;
- чужой, истёкший, отозванный или неподходящий грант приводит к отказу;
- повторный отзыв безопасен и сохраняет время первого отзыва;
- ограниченное окружение соблюдает границы доступа;
- аудит позволяет сопоставить выдачу, запуск, результат, отказ и отзыв без раскрытия секретов;
- обновление сохраняет рабочее состояние, а после перезагрузки восстанавливаются службы, локальные каналы и их права;
- ошибки проверки и повреждённое состояние не приводят к выдаче дополнительных полномочий.

Автоматизированные тесты и результаты приёмки пока не опубликованы. Текущий скрипт `npm test` — заглушка.
